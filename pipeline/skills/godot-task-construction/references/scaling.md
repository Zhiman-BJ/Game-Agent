# 批量生产

用于把同一构题方法扩展到大批任务。目标是持续产出合格且有差异的完整功能任务；不要先编一份固定题型清单，再强行套入不同仓库。

## 维护轻量候选台账

复用现有索引、JSON 或数据库，不为使用 skill 新建服务。各候选至少能检索以下信息：

- 来源仓库、固定版本、衍生家族、任务与 grader 版本。
- 单一功能目标、行为边界、涉及的保留组件及待补关系。
- 缺失策略、难度画像、输入/显示条件与验证方式。
- 最相近的已有候选、实质差异、重复判定及理由。
- 当前阶段、质量结果、证据位置、未解决问题及成本。
- 若已做独立求解：模型和 agent 配置、预算、采样次数、结果及失效类别；否则明确未校准。

这些是语义字段，映射到宿主 schema；不要擅自往严格 schema 添加不支持的字段。宿主没有承载位置时放入独立的私有批次索引。

## 扩量顺序

仓库筛选先看“入口能运行、存在完整玩家操作、依赖可追踪、能形成真实缺口且可验收”。已有这些证据的来源通常更适合先试产；这是降低构造不确定性，不是按玩法简单程度选题。不要在同一候选上同时发明新玩法、重搭上游工程和全新测试体系，再指望最终 Review 一次兜底。

1. 先检查来源可运行性与已有任务分布，形成仓库级能力和依赖摘要。
2. 按当前缺少的依赖形态、能力维度和来源分布提出一批候选，在实现前去重和设计审查。
3. 构造并完成参考/起点检查、validator 对照与最终审查。统计卡在哪个阶段以及修复成本。
4. 修复共性流程问题，再开展下一批；保留成功和失败候选，避免重复探索已知失败方向。
5. 按实际合格数量追踪目标。候选总数可以多于目标，但重试和扩量遵守已给预算；不足时如实报告，不靠放宽门槛补足。

批次大小、每个来源的数量、并发和重试次数由运行成本与约定决定，不在 skill 固定。没有量化预算时先完成有限批次，不自行开启无限生成或付费模型采样。

按失败所在阶段决定下一步：设计过薄/重复先修选题或淘汰；start/reference 失配先修构造；大量合法解误拒先校准共享观察方法；环境问题先修宿主。保留未合格候选及已知原因，不在另一个作者会话中换名从头再造。并行作者共享只读来源与基线摘要、写入独立任务目录；同仓库兄弟题要共享边界摘要，防止重复选题或把对方目标修复当作本题通用准备。

## 语义去重与分布

优先比较“公开行为 + 待补依赖关系 + 起点保留/缺失范围 + 必须处理的状态与边界”。文件哈希和文本相似度可筛选近邻，但最终判定需要看功能语义。

- 改名称、资源外观、默认参数、场景布置或题面措辞，若实现问题基本不变，应标为变体而非独立新题。
- 不同仓库也可能要求相同的构造过程；同一仓库则可以承载实质不同的功能。仓库数不能代替多样性判断。
- 若两个候选可用同一补丁模板经机械替换直接完成，检查它们是否仅为同族变体；不能仅凭模板相似自动删掉实质差异。
- 保留派生关系。需要数据划分时按用户策略处理同源/近重复；用户允许同源构题时无需阻止，但不能称为仓库域外。

发现变体时选择保留为有明确用途的变体，或从独立任务数中剔除。不要静默删除已经验收的产物。以用户范围和当前缺口指导分布，不为填配额添加无关需求。

## 结构难度与实测难度分开

构造阶段先筛掉局部补丁式、整合已被代做或靠歧义变难的候选。用 [难度画像](design.md) 与已认可的基线比较；修改文件数、文件类型、题面字数、测试数和求解步数只作描述统计，不单独作为难度门槛。

只有已授权的独立求解实验才能校准教师与学生差距：

- 固定公开任务与 grader 版本，隔离作者、参考解和隐藏测试；求解者只收到公开输入。
- 记录模型实际版本、agent/工具、技能、上下文、预算、采样与终止条件。比较模型时尽可能保持其他条件一致，差异必须披露。
- 报告每题的尝试数、功能/接口/执行错误、成功率及成本。小样本保留不确定性，不把一次成败写成稳定能力边界。
- 教师与学生都容易通过时，回查是否确有待补接入及测试深度；两者都失败时，先查可行性、规格、环境和预算，再判断是否过难。
- 理想候选需要公平验收下可重复观察的能力差距。不能靠隐藏限制、脆弱路径要求或验收漏洞筛出“差距”。

用于筛选难度的求解结果属于构题校准数据；后续报告新任务泛化能力需要按用户计划保留未用于选择的任务。不能将筛选后差距当成对任意新任务的无偏估计。

## 复用与隔离

可以按源码/引擎/依赖/准备步骤的哈希缓存不可变源材料、导入准备和基线摘要。每个候选在独立可写目录中构造，避免修改共享源、相互覆盖或在 solver 包带入私有材料。

基线缓存只支持同一准备版本，不能代替新 start 和 reference 的实际运行。复用验证工具可以，复制不匹配的新需求断言不可以。任务质量证据绑定完整输入与执行配置，不能把一次仓库通过扩展成所有任务通过。

从合格题复用的是：选题与删改决策、公共运行协议、输入/观察机制、证据格式。每题特有的数值、对象定位、判分断言和合法变体需要重新依据公开规格确认。同仓库共享源材料不等于共享完全相同的 prepared baseline。

失败重试从已保存的有效阶段恢复；修改了上游依赖的产物应使下游证据失效。只重跑受影响工作以控制成本，但每个最终版本仍须满足全部发布门槛。

给下一作者/审查者的交接只保留：当前功能与边界、source/preparation/spec/grader 指纹、关系与差异摘要、已完成检查的位置、未解决发现和下一项动作。原始日志留在证据文件；按问题读取，不反复把整批工程、旧对话和测试输出拼进每个 prompt。首份独立 Review 仍先读公开包，不能由作者结论替代。

## 批次报告

将候选数、通过设计审查数、完成构造数、质量合格数、重复变体数、待复核/失败数分别列出。说明分母、版本和筛除原因，统计质量合格率、各阶段成本、来源/能力分布和已校准比例。

同时报告首份完整独立 Review 的通过数/已完成首审数，以及修订预算内最终合格数/全部候选数；列出未到首审和审查未完成者，不能从分母静默删除。说明宿主人工恢复、额外挑战与返修轮次。不要拿一个最终封存集合的数量与另一个有限返修批次的通过率直接比较。

优化流水线时按问题来源统计，而非只看总合格率：功能过薄/重复、起点损坏、参考缺陷、validator 漏判、validator 误拒、证据不完整、环境/调用失败。尤其观察高风险校准后仍流入 Review 的缺陷数和每道合格题成本；更多测试、更多 token 或更长题面本身不代表提升。沿用质量门槛，不通过删反例、限制合法解或重分类未合格样本改善数字。

任务质量、难度校准、教师成功和轨迹可训练性分别记录。没有模型实验时，只报告结构难度假设；没有新批次验证时，不声称 skill 已提升产量或成功率。
