# 质量基线与构题决策实例

用于把 SF01–SF06 和后续 33 道封存任务的方法迁移到新仓库。编号仅用于追溯，不要求当前环境拥有旧工程；本文件供构题者使用，不随 solver 包发送。按阶段路由读取，宿主可用 quality_profile 固定版本。

## 五项共同证据

- **完整功能：**一个可交付玩家目标，核心机制与真实接入仍待实现；不按文件数、行数或名称判断。
- **合适起点：**目标缺失，原入口及公开保留能力正常；共同准备与目标工作分开。
- **公开契约：**每项强制行为可独立理解、每条判定有公开依据，允许合理实现变化。
- **有效验收：**reference 通过、start 因目标缺失失败，目标/保留行为有有效错误对照，高风险观察有合法变体挑战，必要画面实际审阅。
- **可信交付：**实际公开导出可运行、未泄漏答案；最终版本和证据一致，未完成项不能自动记为通过。

这些是本任务集经验，不冒称外部 benchmark 的统一规则。33 题是修订后的合格集合，K3/Qwen 难度差距未测量。

## 实例一：建塔与升级出售如何拆题（001/002）

**观察与选择：**同一塔防工程包含商店、经济、地图、塔及战斗。001选择“从商店拖出并合法部署一座可战斗的塔”；002选择“管理已建塔的升级与出售”。两者有不同的用户入口、状态变化和完成条件，不按脚本拆题。

**保留与缺失：**001保留角色/经济数据、波次、原塔攻击及升级能力，删除购买拖拽生命周期、预览/建造状态和部署交易。002保留建塔与战斗，缺失选中详情、升级属性与扣款、出售回收与清理的接入。

**公开与验收：**购买题要求真实操作使经济、占用和战斗实例一起成立；管理题要求实际属性/金币/场景状态一致。引用原数据作为输入，不把参考私有 HUD 布局当要求。

**迁移判断：**同仓库多题需各自有完整待补事务，另一系统作为真实背景。不能按每种塔、资源皮肤或一个按钮信号拆出多题；也不要求新题必须包含经济系统。

## 实例二：拖放拼图与保存继续的来源不同（003/004）

**观察与选择：**003恢复拼块操作闭环。004的上游没有现成 session save，是基于工程的扩展，不能宣称已从上游验证了完整存档答案。

**保留与缺失：**003保留难度、图片缩放、棋盘和拼块生成及原资产，删除输入/拖放、占用、完成和得分连接。004则保留完整拼图玩法，先实现持久保存、菜单继续及棋盘重建，再构造缺少这条新链的 start。

**公开与验收：**保存目标是恢复图片、位置/占用、得分与完成状态并能继续操作；文件格式、内部表示和 UI 组织不必等同参考。该题用不同存储实现检查此自由度。

**迁移判断：**已有玩法可作为新任务的基础，缺口不必来自原作者已实现的功能。扩展必须明确来源、建立可行参考；恢复几个内存变量而未经历实际重新加载，不能证明持久化完成。

## 实例三：修复放在准备还是目标中（017/036）

**017 跨月结算：**保留单株生长与增长计算器，把全田编排、日历和界面返回留给求解者。上游作物 family 跟踪及零氮消耗问题被作为明确的共同准备修正，start/reference一致；它们没有提供月末编排。

**036 植物搬移：**无地面 tile 时沿用上次地面类型，会让非法位置继承泥土资格。这个 guard 属于本题放置规则，修复应留在 reference，不能作为准备预先供应给 start。任务虽集中在少量文件，仍包含取格、植物身份、携带和合法放置的完整操作。

**迁移判断：**准备与目标的界线取决于本题承诺和缺口，不取决于 bug 是否来自上游或补丁长短。原仓库 bug 不必全修，也不必一律保留；每次说明为何是非目标依赖或目标机制。

## 实例四：移动与攻击的共享依赖（029/030）

**观察与选择：**同一个资源驱动的战术原型，移动和攻击分别形成可验收操作。移动题保留攻击，攻击题保留移动；资源定义、地图和事件系统继续提供真实背景。

**构造决定：**030移除攻击点击分发、角色动画/信号、伤害与生命反馈、特效和回合继续的目标连接，保留动作资源与移动。准备修复按各题边界安排，不能给两份 start 都预填它们各自需要实现的事务锁。

**校准决定：**按真实角色语义与动作生命周期观察，避免只读数组顺序或固定帧号成为隐藏要求；保留移动也有真实输入和破坏保留移动的对照。

**迁移判断：**保留资源并不自动泄漏完整答案；关键在于求解者是否还需实现资源消费者和协调提交。需要的时序由公开行为决定，不把参考调度固定成唯一解法。

## 实例五：同一功能的范围控制（025/035）

**025 王车易位：**选择双棋子移动的完整闭环：资格/提示、真实占用、协同移动、单次回合和历史。原上游虽能跑四种易位，仍有目标攻击安全规则需要修正；reference补齐目标，但不扩成全部国际象棋合法性重写。消融贯穿King、Board、棋子执行和Tile标记，普通移动/吃子仍保留。

**035 帮手接力：**保留人类玩家和原菜单/按钮/回放，删除自动帮手机制、world创建/信号、manager分配与路由等协作。颜色是同一接力规则的变化，不是多道题。验收终态时先观察公开终态再准备下一局，不能覆盖了旧状态才检查重置。

**迁移判断：**多个对象或多个阶段可以组成一个功能；应以共同玩家结果界定范围。完整功能不意味着顺带加入整个规则体系，也不要求每题都添加终局/重启机制。

## 淘汰实例：薄关卡推进（020）

该候选只有较薄的关卡推进回调，又与已有推进任务接近，未形成足够的完整功能接入工作，最终淘汰且不计入33题。增加文件、把同一回调拆成几段或替换关卡皮肤不会自动解决这个问题。可换一个有真实机制与协作的边界；如果原仓库没有合适空间，允许不出题。

## 使用这些经验时

先按当前源码与实际运行作判断，再选相关实例帮助解释。不要照抄任务数值、接口、文件数量或验收漏洞。设计细则见 [design.md](design.md)，具体构造见 [construction.md](construction.md)，观察校准见 [validation.md](validation.md)。规模、每仓库配额、划分策略和预算来自本批宿主；历史500题目标不构成通用 skill 的执行指令。
