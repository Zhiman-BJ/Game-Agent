# 验收与质量门槛

用于 validator 制作、任务质检和漏判/误拒修订。质量门槛不随批次规模降低；对照通过仅支持已检查的性质，不是正确性完备证明。

## 先定义判定协议

沿用宿主的检查 ID、报告 schema、必需检查集合、完成标记、退出码和错误分类。确认运行器如何注入 validator、收集结果及处理显示需求，再编写测试；不要猜测工具 API。

在隔离副本上测试最终工程，记录实际 Godot 版本、参数、时间与随机性设置。所有强制判定须有公开依据，所有强制需求须有完成的验收路径。运行记录必须关联实际输入和测试版本。

工程副本不自动隔离输入焦点、显示、导入缓存与 `user://` 存档。按实际风险设置独立执行环境；有存档的任务按用例隔离用户数据，测试恢复时只在同一有意配对的保存/读取序列中复用。交互并发按 [API 执行与恢复](api-execution.md) 隔离显示或串行。共同兼容准备应对 start、reference 和对照一致应用并单独记录。

区分行为不满足、公开接口缺失、被测工程故障与验收执行错误。模型导致的语法/运行故障可以使提交不通过；但它不能作为错误对照有效检出某条行为缺陷的证据。validator 崩溃、环境不可用、无效报告不能伪装成游戏功能结论。

## 先校准观察，再扩展矩阵

Construction 内先完成一个有辨别力的小闭环，不增加固定阶段或模型调用：

1. 从原入口用真实操作触发功能，确认 reference 的目标和邻接保留能力可观察，start 在同一操作下确实缺失目标。
2. 检查整个测试驱动程序的假设，选择会影响判分的高风险假设，用针对性合法变体与行为错误变体成对校准；先证明变体自身满足/违反公开要求，再解释验收结果。
3. 保存预期与实际检查 ID、前置状态、关键事件/画面和输入指纹。reference 或合法变体误拒、缺陷漏判、夹具未到位时先修局部观察，不展开昂贵的全矩阵与稳定性重复。
4. 局部校准通过后补齐全部目标/保留要求的对照、适用视觉复核、稳定性及导出检查。它是成本前置筛选，不能代替最终质量门槛。

将下表的适用项写进现有 coverage 或审查记录，记录代码位置、公开依据/允许变化、选取的挑战和实际结果。审计包括辅助函数和诊断代码；即便它不直接返回 verdict，也可能使合法候选崩溃或根本进不了检查。

| 驱动程序中的依赖 | 需要校准的问题 |
|---|---|
| 对象发现、遍历、分类、计数 | 是否偷用了私有类、父节点、固定数组顺序、纹理 identity？公开只读集合若无序，倒序或变序仍应通过；依据公开语义定位实体。 |
| 夹具写字段、连信号、覆盖参数 | 是否要求未公开私有成员？是否替求解者补好了接线，或覆盖了应验收的场景默认值？可选内部能力不能变成必需前提。 |
| 原生输入和空间定位 | 输入是否真正被消费？坐标是否经过实际 Canvas/viewport 变换？节点重挂接或合法布局变化仍应击中真实目标。 |
| 等待、采样和计时原点 | 是否按参考实现的帧号拍照，错过合法快/慢实现？使用实际事件及公开期限；测试等待上限不能暗变成更短的产品期限。 |
| 清理、归属、生命周期 | 是否把释放对象或某种树归属当作“已消费/死亡/结束”？按真实活跃状态、作用、重入和清理义务观察，接受合法池化或释放。 |
| 期望值、诊断与结果聚合 | 是否从候选的错误默认值计算预期，或读取私有诊断字段导致误拒？预期来自公开契约和受控输入；缺失结果不能默认通过。 |

不要求每题制造全部变体。挑选实际依赖的高风险假设；一个变体通过只能支持它挑战的维度，不能证明其它发现/时序/清理分支公平。

## 证明用例确实测到了规则

高风险用例保留以下观察次序：`前置见证 → 原生刺激 → 第一观察 → 必要的后续刺激 → 结束观察`。

- **入口与归因：**确认实际位置、方向、状态和可用输入，而非相信“向左/水域/重启”等用例名称。检查目标规则时，其它拒绝条件必须满足；检查成功时，排除其它炮塔/拼块/角色代为完成。隔离只能用于定点诊断，仍保留原工程完整操作链。
- **默认与变化：**若默认值属于公开要求，先运行未被夹具覆盖的原场景，再测合法配置变化及其真实消费者；不能所有实例先赋值，或用候选自己的默认值定义正确答案。
- **事件前后：**重置、胜利或失效后先读真实结果，再进行下一次 setup。只与“结束后才记录”的快照比较，可能把已经发生的错误当基线；还需检查公开终态条件本身。
- **重入与旧工作：**取消/失败后尽快开始一次合法新操作，保证旧计时器/回调到期时新操作仍在活动，观察新操作不被干扰。只等空闲状态保持安静不足以覆盖此要求。
- **分支可区分：**夹具应使正确规则和待测错误产生不同结果；例如两种寻路策略不能恰好同路。公开允许多种等价结果时接受合法集合，不强制参考的路线或排列。

同一个错误变体可以覆盖多条要求，但每条都要有独立可归因的观察。夹具未到达分支、解析失败或先被另一条件挡住，记为无效覆盖，不能按“出现 FAIL”算检出。

## 对照矩阵

| 对照 | 需要观察到的结果 |
|---|---|
| 原始/准备后的基线 | 实际导入、启动、公开保留能力正常；兼容修复可追踪 |
| start | 基础操作正常；完整验收因目标功能缺失失败 |
| reference | 所有强制行为及适用的视觉验收通过 |
| 有效错误实现 | 仍能运行，在预期违反的公开要求上被拒绝 |
| 实质不同的合法实现 | 满足同一公开规格，完整验收通过 |

为每项强制目标行为及公开保留行为安排能揭露漏判的错误对照，视觉保留项也要有可观察的缺失/错误证据；多个要求可以共用一个变体，但必须有各自可归因的观察，不得用一次早期崩溃算作全部覆盖。优先使用最小行为改动，避免无关缺陷掩盖测试作用。来源/许可证等非行为约束用相应材料检查，不强造游戏负例。

至少保留一份实质不同的合法对照，并针对高风险结构假设增加必要变体。仅重命名变量不够；差异应能检验 validator 是否接受公开允许的实现选择，而不只认参考解内部结构。无需为每个断言重写一整份工程。

若 start 缺少目标组件，validator 应明确报告未实现或必要接口缺失，而不是未经检查地调用空引用。此类结果仍需配合可运行错误实现，证明具体行为规则的辨别力。

## 选择有辨别力的观察

| 风险 | 验收设计 |
|---|---|
| 测试绕开接入 | 至少走通关键真实输入与原入口的完整功能链；直接设状态只作为补充夹具 |
| 只看最终值 | 按公开要求观察必要中间状态、同步关系及结束后的状态 |
| 边界样本太宽松 | 在公开边界两侧和能区分错误近似的位置取样，避免仅测默认配置 |
| 状态或资源串扰 | 检查适用的重复操作、重入、对象增删、独立实例与延迟事件 |
| 组件存在但无实际作用 | 验证真实物理、资源绑定、信号效果和玩家可达操作，不只扫描节点或代码文本 |
| 有数值但无可见效果 | 在规定状态下实际渲染，确认可见性、语义及必要交互效果 |
| 只接受参考解写法 | 依据公开行为检查，避免无依据的对象 identity、私有树层级、算法和文件布局限制 |
| 自报状态与游戏脱节 | 将只读观察接口与真实场景、资源、输入或画面交叉验证 |

对于同一功能的多个配置或子类，选择能分别覆盖不同机制的样本；一个通用字段更新不能证明各子类实际消费了新值。边界应同时有合法内侧和非法外侧样本；例如允许错误空格放置、范围内接近上限的对象，不能只测成功目标和越界。

只测试与公开功能及其保留约束有关的边界。测试输入可以私有，但被测行为范围必须公开；不要为了“增强难度”添加未要求的新规则。

时序检查说明游戏时间或墙钟时间，按引擎与测量误差设置容差。仅对随机、时序等已识别不稳定项重复运行，不能挑一次通过来隐藏间歇失败。

视觉要求不能仅凭变量、`visible` 或截图文件存在判通过。实际审阅所需渲染证据，按公开语义判定；仅在公开要求确需一致时做精确匹配。无显示环境或尚未完成必要复核时保持待处理，不由 headless 通过替代。

逐条审查参与 verdict 的视觉/结构断言：等价画面不必使用相同节点类型、纹理对象、根节点、格子边缘像素或文字字面值。公开允许变化时，合法对照应有针对性地改变表示方式及挂接位置，并保持真实输入、资源绑定和生命周期有效；先确认变体自身正确，再据其判断误拒。多个特效可以共用父容器，一个特效也可以含多个 emitter；父节点数、子节点数都不能直接充当“事务恰好一次”的计数。用合法复合特效和重复事务错误对照配对验证。

有限随机采样没有出现某类型，不能证明它不可达；有限次运行中对象池尚在预热增长，也不能证明它无界。不要据此暗加均匀分布、最小概率、容量或收敛次数要求。采用真实可达见证、适用的行为观察和候选实现的语义审查；需要语义审查时，明确审查依据、候选/验收版本绑定和独立执行者，并把它设为最终判定的必需项。尚未完成时不能自动补 PASS。若现有规则无法可靠验收，返回设计调整公开范围，不能靠私有阈值强行判定。

数值容差只能吸收已量化的测量误差，不能制造未公开的最小速度、最短动画时长、线性增长曲线或更早完成期限。已经明确观测到的缓慢运动，不能仅因位移低于任意像素阈值而判作静止；计时原点应来自实际输入，不能由参考实现的曲线反推。输入辅助函数若隐含等待多帧，应在真实事件前后取样，不能把已经发生的错误跳变当作恢复后的基线。用合法的慢速、非线性、临近公开期限等实现，与静止、越界、超时等错误实现成对检查。较快或较接近参考实现的替代对照通过，不能抹去原先合法反例的失败；必须保留原反例并在最终验收版本上解决。

## 汇总判定

PASS 需要有效、完整的报告，必需检查均已执行且通过，适用的视觉审查完成，并且退出状态与日志符合已声明的成功协议。只有部分绿色断言、没有完成标记或互相矛盾的执行结果，都不足以发布 PASS。

显式保留超时、引擎故障、测试异常和缺失证据。基于证据区分无害清理警告和影响执行的错误，不把所有 stderr 一律判失败，也不把非零退出码一律忽略。人工视觉结论不能覆盖没有完成的行为验收。

采用已有 benchmark 的运行器或规则时固定实际版本。额外增加的复核与接口要求应标明为本任务集的规则，不能未经查证宣称是外部 benchmark 的统一标准。

## 审查与修复

先只读公开输入，形成对功能完成边界和允许实现的判断；再查 reference、validator、覆盖表、对照及原始运行证据。使用独立审查上下文时只移交必要材料；不假装同一作者的复查就是盲审。

1. 保存问题对应的公开条款、实际观察及最小复现材料；先记录挑战预期，再执行。独立 Review 应从公开规格和整个测试驱动程序中选择有风险的漏判及误拒假设，而不只重放作者挑选的对照；已有真实挑战足够时不为凑数无限追加。
2. 定位是规格、start、reference、validator、运行器还是环境的问题。
3. 修复后检查 reference、受影响的合法/错误变体及保留行为；同一观察辅助函数的所有调用点均纳入影响分析。保留原始有效反例并在正式修订版重放，不能只换个更容易通过的变体，或仅修诊断脚本就宣布正式 grader 已修复。修复错误的类型或父节点假设时，还要检查采用同一假设的发现、计数与清理辅助函数；修复旧回调问题时，按公开契约检查相关取消入口和重入流程，不能以单一路径通过概括整个功能。规格改变则返回设计阶段并更新相关产物。
4. 最终版本完成全部发布门槛，记录剩余不确定性及明确状态。没有新风险时不无限追加检查。

独立 Review 已取得有效反例、公开条款及完整正式评分结果，足以证明阻塞缺陷时，可返回修订，不必继续昂贵的剩余矩阵；未完成项明确标为未运行。这只缩短否决路径，最终接受仍须完成全部发布门槛。

当先前合格任务发现阻塞缺陷时，撤销该版本的当前合格资格并保留历史记录；不能继续引用旧的 qualified 标志掩盖问题。

## Godot 时序与条件语义

物理帧信号可能早于 Area2D 拾取处理；按实际引擎/场景核实事件消费与后续处理阶段。图形与无头模式分别保留证据；发生间歇失败时保存位置、事件及阶段信息，用受控实验验证原因。不能挑绿色结果冻结，也不能把没有重建的历史失败归因给后来修复的问题。

前一夹具可能已经触发过关、选项界面或暂停。不要把这种状态残留归为源码缺陷，也不要用测试专用清理掩盖真实流程错误；完成/重启后仍要走通原生操作，数值重置不证明可交互。

保留公开条件句的含义。“若采用分阶段处理，旧回调不得影响新局面”不要求同步合法实现产生中间状态；若公开明确要求动画/飞行过程，则不能只验最终值。选择合法对照时挑战实际时序与表示假设，而非更换变量名。
