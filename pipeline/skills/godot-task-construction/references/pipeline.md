# 流水线接入

用于把 skill 的通用决策规则交给已有构题流水线。这里定义交接语义，不规定新的 CLI、模型、调度器或强制阶段数量。

宿主实际通过 API/CLI 启动并发构题时，再读取 [API 执行与恢复](api-execution.md)。该参考用于调度与证据管理，不授权任务作者自行启动额外模型调用。

## 加载边界

共享 skill 说明范围和质量原则；阶段 prompt 指定当前职责；机器上下文提供真实路径、工具契约、schema、预算和先前证据。三者共同工作，不能只把技能名称写进 prompt 就宣称已加载。

支持原生 skill 的执行器应确认该技能实际可发现，并让作者读取当前阶段所需参考。不支持原生 skill 的执行器可以在构建 job 时，将固定版本的主文与相关参考随阶段上下文提供。对两种方式都保存实际使用内容的快照或可恢复的内容哈希，避免后续修改 skill 改变历史运行含义。

接入代码仅在当前任务授权包含运行器修改时调整。设计了接入约定不等于已修改旧 pipeline；报告应明确这一区别。

## 阶段交接

| 职责 | 输入 | 输出与进入下一阶段的条件 |
|---|---|---|
| 准备与理解 | 固定上游、引擎与环境 | 可运行基线、兼容改动、能力和依赖证据 |
| 理解/提案与规格 | 基线、已有候选摘要、批次约束 | 完整功能、公开需求、缺失计划、难度画像和去重结论；设计审查通过 |
| 工程构造 | 已批准且版本固定的规格与基线 | reference、start、实际接入缺口及改动记录；原入口闭环、目标缺失与保留行为各有证据 |
| Validator 构造 | 公开规格、工程、运行协议 | 先有观察假设和夹具的局部校准，再有完整覆盖/对照矩阵；目标与保留行为的公开依据、有效正反例齐全 |
| 审查与修订 | 公开包、私有质量材料、当前指纹 | 带证据的问题分类和修订；必要检查完成，无阻塞项 |
| 冻结与入集 | 最终产物及合格证据 | 公开包、私有验收包、版本清单、批次索引和准确状态 |

宿主可以合并工程和 validator 构造，也可以有独立的设计审查与修订阶段。按这些职责映射现有阶段，不为凑流程图强行新增模型调用。阶段不能用自由文本“完成”替代实际产物与证据。

Construction 的内部顺序是“可运行完整功能 → 真实操作与观察器小闭环 → 高风险合法/错误变体 → 完整矩阵与导出 → 独立 Review”。校准记录复用现有 coverage/construction_report/evidence 字段；不要向严格 schema 擅自加键。阶段时限和修订预算仍沿用宿主，不把内部检查拆成额外付费调用。

审查可在独立作者上下文执行，先提供公开材料再按需提供私有材料；采用何种方式如实记录。解题实验必须与看过答案的构题上下文隔离。

用户只要求静态预审、流程或技能优化时，交付“范围判断、代码/条款依据、优先挑战及预期、尚缺证据”。未执行的风险标为待验证假设；读到某检查委托视觉/语义审查，但尚未核对运行器时，记录其 gate 强制性待核实。沿用宿主状态表达，不把静态检查改记为真实复现、READY_FOR_REVIEW 或 ACCEPTED，也不自动启动构题。

## 宿主负责机械检查

skill 指导作者如何选择范围、设计缺失、避免泄漏和设计有效测试；运行器负责可机械验证的边界：

- 校验 schema、稳定 ID、路径边界和必需文件，核对规格未被构造阶段擅自改变。
- 调用真实导入、启动、测试与显示检查，保留原始结果并按成功协议汇总。
- 检查目标和公开保留行为的需求 ID 与验收/对照映射完整，禁止缺失检查被默认记为通过。
- 保存输入、skill、prompt、上下文、工具与产物指纹，以及阶段状态和失败原因。
- 由实际验收结果更新资格；作者不能只写一个 approved 或 qualified 标志替代检查。

缺少这些能力时列为接入缺口，不用 prompt 承诺冒充已实现的硬约束。作者仍应执行当前环境可做的检查，并清楚报告证据边界。

机械 gate 验证记录与实际文件、结果的一致性；“夹具可区分”“合法变体确实合法”“观察没有隐藏限制”还需要语义审查。不要新增一个作者可自填的 `calibration_pass=true` 就宣称门槛已落实。质量失败按规格/start/reference/漏判/误拒/运行环境分类路由；不要把所有未合格都归为任务太难或太简单。

## 恢复与版本

工作单包含任务版本、阶段、输入指纹、输出位置、检查状态、问题与下一步。字段名沿用宿主定义；在现有记录可表达时不要再增加重复文件。

重试前先读取失败证据和已完成产物，避免不必要重做。规格变更返回设计审查并失效受影响产物；工程变更使相关运行、对照和最终审查失效；仅 grader 修复保留原判定并产生可追踪的新判定。

恢复时验证输入指纹，不能仅凭文件存在跳过。共享工作区中的任务使用独立写入路径；无需为了 skill 启用并发或多 agent。

## 接入验证

如果任务包含实现接入，先检查生成的 job 实际包含所需 skill 内容、正确阶段参考、机器契约和输入指纹，再用有限完整试运行验证产物能被宿主消费、错误能阻止入集且恢复行为正确。只有完成这些检查才能报告“已接入且验证”。

只做 skill 设计或文档修改时，验证 frontmatter、引用、UI 元数据及约定一致性即可；不自动启动模型 API、任务生成或求解实验。

## 可执行工作单必须提供的内容

对采用三个 prompt 的宿主，Design 加载 design/scaling/quality-baseline，Construction 加载 construction/validation/quality-baseline，Review 加载 validation/quality-baseline，再共同加载本文件和主 SKILL。保存实际字节，不仅保存机器上的技能路径。工作单同时包含固定 run_context、必要前序 spec/coverage 的快照和摘要；Review 先发公开包，再开放私有材料，记录是否真正是新上下文。

`scripts/project_delta.py` 是可选的只读差异工具。宿主若提供本技能的工作单副本，应将脚本随技能快照保存并记哈希，告诉作者实际路径；无需把脚本全文嵌入 prompt。它比较 source/prepared/reference/start 任意两个工程的字节变化，只生成私有报告，不运行 Godot、不认证消融充分或任务资格。脚本不可用时报告能力缺口或使用宿主已验证的等价差异工具，不假装已执行。阶段调用、校准和发布继续使用宿主运行器。

宿主可以提供 render/run/gate/freeze 命令，但 skill 不假设具体 Codex CLI 或 API 参数。调用者提供真实执行器的 argv/工具配置；新 job 不复用旧聊天 session。暂停/失败后恢复须核对输入摘要，变动则生成新 job，不覆盖旧日志。模型返回成功只表示调用结束，产物资格仍由实际检查决定。

最终 gate 至少验证：输入/候选/grader/runner 哈希一致、必需检查齐全、start 基础 PASS 与完整 FAIL、reference PASS、目标及公开保留行为的有效负例在指定检查 FAIL、合法替代解 PASS、适用视觉复核完成、独立 Review 无阻塞项。语义审查核实局部校准、前置见证和独立挑战；状态字段或空证据列表不能代替这些材料。先用故意不完整的工作单和实际试产包验证 gate 会拒绝，再接入 API 扩量。

更新 skill 后，在不调用模型的情况下检查新工作单实际包含各阶段最新参考及其哈希；只修改技能源文件不会更新已快照的 job。保留旧批次输入，给后续 job 固定新版内容。若当前仅授权技能优化，做到静态加载检查并报告未做新批次试产，不启动任务构造来“验证成功率”。
