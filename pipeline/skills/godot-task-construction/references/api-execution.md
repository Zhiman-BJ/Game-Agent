# API 执行与恢复

仅用于宿主已获授权的模型 API/CLI 构题试产。沿用用户选定的执行器、模型、推理强度、并发数和批次范围；本参考不授权额外求解实验或训练。作者读取阶段资料，宿主负责调用、隔离、恢复与验收。

## 预检实际工作负载

先检查本机执行器的真实参数与供应商协议，再跑最小模型回复、工具写读以及该工具环境中的 Godot 导入、原生交互、渲染和图片查看。文本回复或 shell 文件写入成功，不能证明引擎工作负载可用。记录实际引擎/执行器版本及生效配置；不凭模型名称猜测工具或推理选项。

Godot 可能需要本地 socket、显示服务、音频后端和可写的导入缓存。遇到失败，按引擎日志定位环境能力，做有依据的配置修订再预检；不把环境错误计作任务缺失，也不一概关闭隔离。凭据放在独立私有位置，通过执行器支持的凭据通道传入，排除在作者 shell 环境、公开题面和交付包之外。

需要鼠标、键盘或窗口焦点的验收不能同时共用一个显示服务。每个并发交互运行使用独立显示，或在同一显示上串行执行；只为每个作者分配一个显示，不能隔离该作者内部并行启动的多个游戏。将窗口/显示冲突与游戏行为失败分开诊断，保留首次失败证据。

## 分开记录三种状态

- 调用状态：执行器完成、传输失败、人工中止、阶段超时。
- 产物状态：规定文件是否齐全、输入及内容指纹是否一致、能否交接。
- 任务资格：真实质量检查、独立 Review 和最终导出复验是否通过。

流日志中出现过 reconnect/error 不一定表示最终调用失败：核对终止事件、退出码及其含义。反之，正常退出和作者写出的 READY/ACCEPTED 不能代替验收。状态汇总以当前尝试为准；历史 supervisor 的完成记录不能覆盖后来仍在运行的恢复任务。

## 有界恢复

为本批设置阶段时限、传输重试和质量修订边界。失败后先查进程身份、输入指纹、最后事件和已有文件；不要在旧任务仍运行时启动重复作者，也不要同时让两个作者修改同一候选。并发上限针对实际活跃的作者调用计算，记录重试是否占用空槽。

说明并发参数约束的是顶层流水线、全部模型会话还是实际模型请求。原生 harness 可能在一个进程内启动独立审查子会话；只统计 CLI 进程不能证明底层请求的全局上限。若用户要求严格全局上限，使用共享请求限流或宿主统一调度，并验证子会话也受约束。

分别计数供应商流重连、宿主恢复尝试、Construction 内部校准和独立 Review 返回后的修订轮次。限额必须写清所指层级；不能把内部测试次数误作外层修订配额，也不能以恢复调用之名重置已经用尽的质量修订轮次。

保留失败尝试的日志，新尝试另建记录。前阶段已成功且输入未变时可复用已核实的交接，避免重复生成。若调用超时但产物已经写完，只有在宿主独立核实必需材料、源码版本、证据与哈希后才能交接，并明确记录为产物恢复；原超时与缺失的最终用量仍然保留。不能只依据文件存在或 READY 标记跳过阶段。

区分长测试与等待模型：检查实际子进程和产物更新时间，再决定恢复。执行器流空闲时限与整个阶段时限是不同边界。重试耗尽或当前规格无法通过质量门槛时，保留未合格状态及原因，不靠降低要求补足数量。

## 可追溯的会话与成本

保存实际 prompt/skill/上下文快照、执行参数、进程和会话 ID、工具事件、原始执行证据及阶段结果。若 CLI 摘要遗漏图片查看或中断后的工具输出，使用持久会话记录补充审计；不能把简略事件流宣称为完整轨迹。Review 使用独立上下文，先完成公开包阅读，再开放私有材料。

每次调用只选取一份用量来源：完整轮次回执，或清楚标为部分值的最后会话报告。无回执是未知，不是零；缓存输入与推理输出通常是各自总量的子集，按实际字段语义统计，避免重复相加。不知道供应商计价时不虚构金额。构题工具调用数与教师解题 step 数分别报告。

识别原生父子会话关系，核对父回执是否包含子会话用量。若父 CLI 回执仅匹配父会话自己的计数，则将子会话独立计入一次，并按 session ID 去重；不要用整个目录最后一份 token 记录替代父会话，也不要遗漏子会话。分别记录它们实际使用的模型、推理强度、完整/部分用量和审查身份。

## 冻结与下一批

先完成评分器代码、清单版本和序列化格式，再固定字节运行完整矩阵；之后的观察与报告写入私有证据文件。评分器字节变更后，旧证据不能改写哈希冒充新运行。若仅为意外格式改动，可核实并恢复已测试的原字节；实际逻辑变化应重新建立受影响证据。

本批开始后固定工作单所用版本；新经验进入下一版 skill/运行器，不悄悄改写历史输入。必要的本批修订单独留存旧版和原因。最终核对导出字节与已验收工程一致，仅将合格任务加入新版本去重清单。报告合格数、未合格原因、恢复开销和难度校准状态；五路启动成功不能证明大规模无人值守生产已经可靠。
